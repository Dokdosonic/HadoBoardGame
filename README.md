# HadoBoardGame
# HADO 스마트 보드 프로젝트

## 1. 프로젝트 소개

HADO 스마트 보드는 AR 스포츠 HADO를 실제 보드게임 형태로 구현하는 프로젝트이다.

기존 HADO는 AR 기기를 착용하고 가상 공간에서 공격과 방어를 진행하는 스포츠이다. 이 프로젝트에서는 HADO의 움직임과 전략 요소를 물리적인 보드게임으로 재구성하고, 기물의 위치를 전자회로로 감지해 컴퓨터에 표시하는 시스템을 개발한다.

보드의 외형은 체스판을 활용하지만, 기물은 바둑처럼 격자선이 만나는 교차점에 배치한다.

**9×9 격자의 총 81개 교차점**을 감지 위치로 사용하며, 각 팀은 조작 패드에서 이동할 기물을 선택한 뒤 실제 보드에서 기물을 움직인다.

서버는 센서가 감지한 위치 변화와 패드에서 선택한 기물 정보를 결합하여 기물의 위치를 실시간으로 업데이트한다.

초기에는 소형 보드에서 시스템을 검증하고, 이후 대형 보드로 확장하는 것을 목표로 한다.

## 2. 프로젝트 목표

- 9×9 격자의 총 81개 교차점에서 기물 점유 여부 감지
- 1~6번 기물의 초기 위치 등록 및 이동 추적
- 각 팀의 조작 패드를 통한 기물 선택
- 경기 시간, 턴수, 스킬 사용 관리
- Raspberry Pi Pico와 GPIO 확장 IC를 이용한 감지 회로 제작
- 컴퓨터에서 보드 상태와 경기 정보 실시간 시각화
- 납땜 없이 제작할 수 있는 회로 구성
- HADO 방식의 공격 및 방어 규칙 구현
- 소형 프로토타입 완성 후 대형 보드로 확장

## 3. 시스템 구성

### 3.1 하드웨어

| 부품 | 수량 | 용도 |
|---|---:|---|
| Raspberry Pi Pico 2 W | 1개 | 메인 컨트롤러 |
| MCP23017 (DIP-28) | 6개 | GPIO 입력 확장 |
| 8×8칸 플라스틱 체스판 | 1개 | 9×9 교차점 게임 보드 |
| 반원형 금속 접점 | 162개 | 81개 교차점의 점유 감지 |
| 전도성 금속 기물 | 6개 | 양 팀의 게임 기물 |
| 팀별 조작 패드 | 2대 | 기물 선택 및 경기 조작 |
| 브레드보드 | 필요 수량 | 회로 구성 |
| 점퍼선 | 다수 | 회로 연결 |
| 저항 및 커패시터 | 필요 수량 | I²C 통신 및 회로 안정화 |

※ MCP23017 하나는 16개의 GPIO를 제공하며, 6개를 사용하면 총 96개 입력을 확보할 수 있다. 이 중 81개를 사용하고 15개는 예비 입력으로 남긴다.

### 3.2 보드 구조

- 보드 형태: 체스판 기반
- 격자선: 가로 9개, 세로 9개
- 기물 배치 방식: 바둑과 동일한 교차점 배치
- 감지 위치: 9×9, 총 81개 교차점
- 보드 재질: 플라스틱
- 각 교차점에 서로 분리된 금속 접점 2개 설치
- 금속 접점은 원형 철제 디스크를 반으로 절단한 반원형 구조로 제작 예정
- 반원형 접점 사이에는 약 1~2mm 간격 유지
- 기물이 두 접점을 동시에 연결하면 해당 교차점을 점유한 것으로 판단

일반적인 8×8칸 체스판은 가로와 세로의 경계선이 각각 9개이므로 총 81개의 교차점이 존재한다.

본 프로젝트에서는 이 81개 교차점을 모두 감지 위치로 사용한다.

#### 접점 제작 방법

1. 얇은 원형 철제 디스크 준비
2. 금속 절단용 공구를 이용해 반원 2개로 분리
3. 절단면의 날카로운 부분 제거
4. 보드의 각 교차점에 반원형 금속 접점 2개 설치
5. 두 접점이 서로 닿지 않도록 고정
6. 접점에 점퍼선을 연결해 감지 회로 구성

총 81개의 원형 디스크를 절단하면 162개의 반원형 접점을 제작할 수 있다.

※ 철제 디스크의 실제 절단 가능 여부, 접점 고정 방식, 배선 연결 방식은 추가 실험이 필요하다.

### 3.3 기물 배치 및 초기 위치

경기에는 총 6개의 기물을 사용한다.

- RED 팀: 1번, 2번, 3번 기물
- BLUE 팀: 4번, 5번, 6번 기물

각 기물은 고유 번호를 가지며, 경기 시작 시 배치되는 초기 위치가 정해져 있다.

서버는 경기 시작 전에 1~6번 기물의 초기 좌표를 등록한다.

이후 각 팀의 조작 패드에서 이동할 기물을 선택하고 실제 보드에서 기물을 움직이면, 센서가 감지한 위치 변화를 바탕으로 해당 기물의 좌표를 업데이트한다.

좌표는 X와 Y를 각각 1~9 범위로 설정한다.

## 4. 점유 감지 원리

각 교차점에는 두 개의 금속 접점이 존재한다.

- 접점 A: GPIO 입력
- 접점 B: GND
- GPIO 입력: 내부 풀업 저항 사용

기물이 없는 경우 두 접점은 전기적으로 분리되어 있으므로 입력값이 HIGH(1)이다.

전도성 금속 기물이 두 접점에 동시에 닿으면 GPIO와 GND가 연결되면서 입력값이 LOW(0)로 변경된다.

| 상태 | GPIO 입력값 | 판정 |
|---|---|---|
| 기물 없음 | HIGH (1) | 빈 위치 |
| 기물 있음 | LOW (0) | 점유된 위치 |

이 방식을 81개 교차점에 적용해 보드 전체의 점유 상태를 감지한다.

## 5. 자석 활용 계획

기물의 위치를 안정적으로 유지하기 위해 자석을 활용하는 방법도 검토하고 있다.

현재 검토 중인 방식은 보드 아래에 자석을 설치하고, 기물 바닥에는 자석에 반응하는 금속 부품을 사용하는 것이다.

단, 전기적 점유 감지를 위해 기물 바닥의 접촉 부분은 전도성을 유지해야 한다.

자석의 위치와 세기는 실제 기물 이동에 영향을 줄 수 있으므로 테스트를 통해 결정할 예정이다.

## 6. 회로 설계

### 6.1 Raspberry Pi Pico 2 W

Pico 2 W를 메인 컨트롤러로 사용한다.

주요 역할은 다음과 같다.

- MCP23017과 I²C 통신
- 81개 입력 상태 수집
- 점유 상태 변화 감지
- 컴퓨터 또는 게임 관리 서버로 감지 데이터 전송

### 6.2 MCP23017

MCP23017은 16개의 GPIO를 제공하는 I²C 기반 확장 IC이다.

총 6개의 MCP23017을 사용해 81개 교차점을 감지한다.

| MCP23017 | I²C 주소 | 담당 감지 위치 |
|---|---|---|
| 1번 | 0x20 | 1~16번 |
| 2번 | 0x21 | 17~32번 |
| 3번 | 0x22 | 33~48번 |
| 4번 | 0x23 | 49~64번 |
| 5번 | 0x24 | 65~80번 |
| 6번 | 0x25 | 81번 및 예비 입력 15개 |

주소는 각 IC의 A0, A1, A2 핀 연결로 설정한다.

각 MCP23017의 GPIO는 입력 모드로 설정하고 내부 풀업 저항을 활성화한다.

### 6.3 배선 방식

- Pico와 MCP23017은 I²C 버스로 연결
- 모든 MCP23017은 공통 GND 사용
- 각 교차점의 금속 접점 하나는 MCP23017 입력 핀에 연결
- 다른 금속 접점은 공통 GND에 연결
- MCP23017은 3.3V 전원 사용
- I²C의 SDA, SCL 라인에 적절한 풀업 저항 적용
- 납땜 없이 브레드보드와 점퍼선으로 구성

## 7. 소프트웨어 개발 계획

### 1단계: 단일 접점 감지

Pico의 GPIO 입력 하나를 사용해 기물 접촉 여부를 감지한다.

### 2단계: MCP23017 연동

MCP23017 하나를 연결해 16개 입력을 읽는 기능을 구현한다.

### 3단계: 81개 교차점 감지

MCP23017 6개를 연결하고 전체 81개 교차점의 점유 상태를 수집한다.

### 4단계: 컴퓨터 시각화

컴퓨터에 9×9 교차점 보드를 표시하고 실제 기물 점유 상태를 실시간으로 반영한다.

표시할 정보는 다음과 같다.

- 교차점 좌표 (X, Y)
- 점유 여부
- 점유 상태 변화
- 기물 번호
- 기물 이동 기록

### 5단계: 팀별 조작 패드 개발

경기는 두 팀이 각각 별도의 조작 패드를 사용하는 방식으로 진행한다.

각 팀은 패드에서 이동할 기물을 선택하고, 스킬 사용 여부와 턴 진행을 관리한다.

경기 시간과 턴수는 게임 관리 서버에서 통합 관리한다.

#### 팀별 조작 패드 기능

- 현재 경기 시간 표시
- 현재 턴 및 남은 행동 횟수 표시
- 이동할 기물 선택
- 선택된 기물의 현재 좌표 표시
- 스킬 선택 및 사용
- 이동 확정 및 취소
- 팀별 상태 및 점수 표시

### 6단계: 기물 이동 추적 시스템

총 6개 기물에는 1~6번의 고유 번호를 부여하며, 경기 시작 시 각 기물의 초기 배치 위치는 고정되어 있다.

#### 기물 이동 처리 과정

1. 경기 시작 시 1~6번 기물의 초기 좌표 등록
2. 각 팀의 조작 패드에서 이동할 기물 선택
3. 서버에서 선택한 기물의 현재 위치 확인
4. 실제 보드에서 기물을 들어 올리면 기존 교차점의 점유 해제 감지
5. 기물을 새로운 교차점에 놓으면 해당 위치의 점유 감지
6. 서버에서 선택된 기물의 좌표 갱신
7. 이동 결과를 각 팀 패드와 경기 화면에 실시간 반영
8. 게임 규칙에 따라 턴 및 행동 횟수 갱신

#### 기물 식별 방식

각 교차점의 접점 센서는 기물의 존재 여부만 감지한다.

그러나 경기 시작 시 기물의 초기 위치가 정해져 있고, 이동 전에 패드에서 기물 번호를 선택하기 때문에 별도의 기물 ID 인식 센서 없이도 위치 추적이 가능하다.

서버는 선택된 기물의 기존 좌표와 실제 보드에서 발생한 점유 상태 변화를 비교하여 기물 이동을 판정한다.

단, 동시에 여러 기물이 이동하거나 예상하지 못한 위치 변화가 발생하면 자동 확정하지 않고 오류 처리 및 재확인 절차를 진행한다.

### 7단계: HADO 게임 규칙 구현

기물 이동 데이터를 활용해 공격, 방어, 점수 및 게임 진행 기능을 개발한다.

경기 규칙에 따라 기물별 이동 가능 범위, 스킬 사용 조건, 턴 진행 방식 등을 설정할 예정이다.

## 9. 기술적 한계 및 해결 과제

### 9.1 기물 식별

현재 방식은 각 교차점에 기물이 있는지 여부만 감지한다.

기물의 초기 위치와 패드에서 선택한 기물 번호를 활용하면 이동 추적이 가능하지만, 여러 기물이 동시에 이동하면 정확한 판정이 어려울 수 있다.

이를 방지하기 위해 이동 선택 및 확정 절차를 적용할 예정이다.

### 9.2 접점 불안정

금속 접점의 산화, 오염, 접촉 압력에 따라 감지가 불안정할 수 있다.

소프트웨어 디바운싱과 접점 구조 개선을 통해 해결할 계획이다.

### 9.3 배선 복잡성

81개의 입력을 개별적으로 연결해야 하므로 배선량이 많다.

공통 GND 배선과 MCP23017을 활용해 회로 구성을 정리할 예정이다.

### 9.4 기물 이동 경로 추적

접점 방식은 각 교차점의 점유 상태만 확인할 수 있다.

따라서 기물이 교차점 사이를 이동하는 동안의 연속적인 위치나 실제 이동 궤적을 직접 측정할 수 없다.

이동 전후의 점유 상태를 비교하여 이동을 추정하는 기능을 우선 개발한다.

### 9.5 패드와 보드의 상태 동기화

패드에서 기물을 선택했더라도 실제 보드에서 다른 기물이 이동할 수 있다.

서버는 선택된 기물의 기존 위치와 센서 변화가 일치하는지 확인해야 한다.

불일치가 발생하면 이동을 확정하지 않고 재확인 절차를 진행한다.

## 10. 최종 목표

최종적으로 실제 보드 위에서 기물을 움직이면 컴퓨터 화면의 보드 상태가 자동으로 갱신되고, 이를 기반으로 HADO의 공격과 방어 요소를 구현하는 시스템을 완성하는 것이 목표이다.

각 팀은 별도의 조작 패드로 기물 이동과 스킬 사용을 관리하며, 경기 관리 서버는 경기 시간, 턴, 기물 위치, 점수 등을 통합 관리한다.

이를 통해 물리적인 보드게임과 전자회로, 프로그래밍을 결합한 인터랙티브 게임 시스템을 제작하고자 한다.

## 11. 향후 확장 계획

본 프로젝트는 소형 9×9 교차점 보드를 활용한 프로토타입 제작을 시작으로, 최종적으로 대형 HADO 보드게임 시스템을 구현하는 것을 목표로 한다.

### 1단계: 소형 프로토타입 검증

- 81개 교차점 점유 감지 시스템 구현
- 1~6번 기물의 초기 위치 등록 및 이동 추적
- 팀별 조작 패드와 경기 관리 서버 연동
- 경기 시간, 턴, 스킬 사용 기능 구현
- 기물 이동 오류 및 접점 안정성 검증

### 2단계: 대형 보드 제작

- 기존 9×9 교차점 구조를 유지하면서 보드 크기 확대
- 대형 기물과 접점 구조 제작
- 배선 길이 증가에 따른 신호 안정성 검증
- 대형 보드에 적합한 하드웨어 구조 개선

### 3단계: 경기 시스템 완성

- 실제 대형 보드에서 HADO 게임 진행
- 양 팀 조작 패드와 경기 전광판 연동
- 공격 및 방어 스킬 구현
- 경기 결과와 기물 이동 기록 저장
- 실제 플레이 테스트를 통한 규칙 개선

소형 프로토타입에서 개발한 소프트웨어와 게임 규칙을 최대한 재사용하여 대형 시스템으로 확장할 계획이다.
